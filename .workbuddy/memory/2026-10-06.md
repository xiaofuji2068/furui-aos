## 意外发现：并发会话在同一仓库操作

- 现象：我 `Edit` README 后执行 `git add -A && git commit`，却收到 `nothing to commit, working tree clean` + `ahead of origin/master by 1 commit`。
- 真相：提交 `d6dbe54`（20:22:50）由**另一个会话/窗口**在我改动落盘后抢先提交了，我的 commit 因此无变更可提交（`&&` 链断在 commit 处，后续 echo 未执行，一度误以为改动丢失）。
- **教训**：多会话同时操作同一仓库时，`nothing to commit` 不等于改动丢失 —— 先用 `git log origin/master..HEAD` + `git show --stat HEAD` + `grep -c <关键字> README.md` 三者交叉确认，再决定是否重做。
- 判断改动是否真的在：`git show HEAD:README.md | grep -c "关键字"`（查 HEAD 版本）/ `grep -c`（查工作区）。
