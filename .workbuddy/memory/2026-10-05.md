### 新增环境经验
- `git ls-files | while read f; do stat -c%s ...` 在这台 Windows bash 上会超时被 SIGTERM（`stat -c` 不受支持 + 逐文件起进程）→ 改用 `git ls-files -z | git cat-file --batch-check`，或直接 `git show --stat HEAD | tail` 看体积分布更快。
- 首次提交后**一定要复查 `git show --stat`**：索引经过多轮 `git add -A` 重组时，容易把历史排查产物（dump/截图/抓取 json）混进来；`git ls-files | wc -l` 只给数量，看不出体积。
- `git rm -r --cached` 要求文件已在索引且未被 `.gitignore` 新规则影响（否则报 staged content different）→ 流程是「改 .gitignore → `git reset -q && git add -A` → `git rm -r --cached <dir>` → `git add -A`」。
