## 林大人 后续发起「模型管理模块页面报错」→ 已修复

### 根因（前端 SSR 空指针）
`frontend/components/ModelKeysCard.tsx` 首屏 `keys` 为 `null`（数据靠 `useEffect`→fetch 异步加载），
但第 107-114 行的 `embedding` 对象直接用 `keys?.embedding.model` / `keys?.embedding.has_key`
构造，`.model`/`.has_key` 在 `keys` 为 null 时抛 `TypeError`，导致整个 `/admin/model` 页面 SSR 崩溃（"Application error"）。

### 修复（两处）
1. **可选链兜底**（行 110-112）：`keys?.embedding?.model || "text-embedding-v3"`、`!!keys?.embedding?.has_key`
2. **空值守卫**（行 116-123）：`if (!keys)` 先返回带 `animate-pulse2` 的占位卡片，等数据加载完再渲染真实内容

### 验证
- `GET /admin/model` → HTTP 200（之前整页崩溃）
- SSR HTML 含 `animate-pulse2` 占位、无 `Application error`
- 真实 provider 卡片（DeepSeek / DashScope 语义模型）在客户端 fetch 完成后渲染——符合预期
- 后端 `/api/admin/model` 与 `/api/admin/model/keys` 返回 JSON 正常，非后端问题

→ 此 P0 级页面报错已闭环；P1/P2（缺 app/admin/page.tsx、main.py root() 过时、config.py model_ 警告）保持未修，待林大人确认是否一并处理。
